# LastMile
## Real-Time Geospatial Logistics & Intelligent Route Optimization Platform

LastMile is an R-based logistics decision-support prototype that selects a suitable
fulfilment outlet by considering road-network travel time, hour-based traffic,
weather multipliers, predicted outlet queues and optional live queue events.

> The nearest outlet is not necessarily the fastest fulfilment option.

### How it works

The road network is represented as a weighted spatial graph. For each request,
edge travel-time weights can be updated using traffic and weather factors. The
system calculates routes from candidate outlets, estimates queue-related
preparation delay, applies service-area and hostel-curfew constraints, and ranks
the feasible outlets by estimated total time.

```text
OpenStreetMap road graph
        |
        v
Network + outlet/order simulation
        |
        v
Queue-demand model + demand hotspots
        |
        v
Dynamic edge weighting (traffic x weather)
        |
        v
Route calculation + queue/preparation scoring
        |
        +------ Optional Redpanda/Kafka -> PostgreSQL live queue
        |
        v
Shiny + Leaflet decision-support dashboard
```

### Important evidence distinctions

- **Road geometry:** downloaded from OpenStreetMap when using the real-network pipeline.
- **Orders/outlets:** generated by the project's simulation script.
- **Traffic:** synthetic hour-of-day traffic levels; not a live traffic provider.
- **Weather:** Open-Meteo current conditions when reachable; a fallback condition is used on failure.
- **Live queue:** optional Redpanda/Kafka-compatible event stream and PostgreSQL integration.
- **Performance results:** must be generated by the included simulation benchmark; they are not real-world delivery measurements.

### Requirements and setup

Use a recent R installation. From the project root:

```r
source("requirements.R")
```

Fast offline/development pipeline:

```sh
Rscript run_pipeline.R --fast
```

Real Chennai OpenStreetMap network (internet required):

```sh
Rscript run_pipeline.R
```

Launch the primary dashboard:

```r
shiny::runApp("app_v2.R")
```

### DA3 experiments

After generating the `.rds` artifacts, run:

```sh
Rscript experiments/run_benchmarks.R
```

The experiment compares four strategies on the same sampled customer nodes and
hours:

1. Static shortest-time routing.
2. Traffic-aware routing.
3. Traffic-and-weather-aware routing.
4. Full queue-aware routing (traffic, weather and predicted preparation delay).

Outputs:

- `experiments/results/routing_trial_results.csv`
- `experiments/results/routing_strategy_summary.csv`
- `experiments/results/paired_comparisons.csv`

The paired comparison includes estimated time differences, confidence intervals
and paired t-test p-values. Results are simulation-based and should be described
as such in the report.

### Streaming layer (optional)

The `streaming/` directory contains a Redpanda-compatible Kafka broker setup,
Python producer/consumer scripts and PostgreSQL persistence. It is optional:
the dashboard is designed to continue in fallback mode when the stream/database
is unavailable. Follow `streaming/docker-compose.yml` and `streaming/requirements.txt`
for the environment-specific setup.

### DA3 deliverables

- Reproducible routing strategy experiment and CSV outputs.
- Interactive Shiny/Leaflet dashboard.
- Interpretation of measured results and limitations.
- Final report, code documentation and viva demonstration.
